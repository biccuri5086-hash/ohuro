# 画面スクリーンショット検証と変更前後の比較（Issue #25 / Art-3）

見た目を変える PR では、変更前後のスクリーンショットを並べて比べる。設定は `scripts/art/shots.config.mjs` の 1 か所だけ。

## 使い方

```bash
npm run art:compare -- --base origin/main
```

- `--base`: 変更前とする git の参照（既定は `origin/main`）
- `--head`: 変更後とする参照。省略すると、いまの作業ツリー（未コミットの変更を含む）
- `--fail-on-diff`: 1 画素でも差があるか、撮影上の問題があれば終了コード 1。**見た目を変えないはずの PR**（素材の取り込みの置き換えなど。Issue #24）で使う

1 回だけ撮る場合（比較しない）:

```bash
npm run build
npm run art:shots
```

## 出力

| 場所 | 内容 |
|---|---|
| `.art-shots/before/`、`.art-shots/after/` | 画面幅ごと・区間ごとの PNG と `manifest.json`（画像の SHA-256、横スクロール、外部通信） |
| `.art-shots/compare/<画面幅>-<区間>.png` | 並べた比較画像（変更前 / 変更後 / 差分。差分は変化した画素を赤で表示） |
| `.art-shots/compare/report.md`・`report.json` | 区間ごとの変化した画素数と割合、撮影上の問題 |

`.art-shots/` はコミットしない（`.gitignore` 済み）。PR には `report.md` の表と、変化のあった比較画像を添付する。

## 撮影条件（固定）

| 項目 | 値 |
|---|---|
| 画面幅 | 360（小型 Android 相当）/ 390（iPhone 13 相当）/ 412（Pixel 7 相当） |
| 倍率 | `deviceScaleFactor: 2`（全画面幅で同じ） |
| 対象 | LP のファーストビュー・課題提起・製品紹介・写真チェックの説明・事前登録フォーム・FAQ |
| URL | `/?ohuro_test=1`（テスト流入として記録され、集計から除外される） |
| 動き | `reducedMotion: "reduce"`、CSS で `animation`・`transition` を停止 |
| フォント | IPA ゴシックに固定（下の注意を参照） |
| 言語・時刻 | `ja-JP`、`Asia/Tokyo` |
| 差分の判定 | 1 画素の各色成分（R/G/B/A）の差が 16 を超えたら「変化あり」 |

自動で確認すること: 横スクロールが出ないこと（`scrollWidth > innerWidth` で検出）、外部への通信がないこと（同じオリジン以外へのリクエストを止めて記録）。どちらかがあれば終了コード 1。

## 基準画像の方針

- **基準画像はコミットしない。** 変更前の画面は、そのつど git の参照（既定 `origin/main`）を別ディレクトリ（`git worktree`）に取り出し、`npm ci` → ビルドして撮る
- 理由: 画像をコミットすると、リポジトリが重くなり、環境差（フォント・ブラウザの版）で古い基準がすぐに合わなくなるため
- 例外: 仕様の記録として残す画像（`docs/art/baseline/`。現行の絵の一覧など）は、所有者の確認を経てコミットする

## 環境差の扱い

- 比較は**同じ環境（同じコンテナ・同じ Chromium・同じフォント）で撮った画像どうし**でだけ行う。`art:compare` は変更前と変更後を同じ実行で撮るため、この条件を満たす
- 別の環境で撮った画像を比べて差が出ても、デザインの変化とは判断しない
- フォントを IPA ゴシックに固定しているのは環境差をなくすため。実機（システムフォント）とは文字の形・折り返しが異なる場合がある
- 差の判定値（16）を超える小さな差が、変更していない区間で出た場合は、まず同じ参照どうし（`--base X --head X`）で比べ、差が 0 になるか確認する。0 にならない場合は撮影条件の問題として Issue にする（判定値を上げて隠さない）

## 実機確認との関係

- ここでの撮影は Chromium のエミュレーションで、**実機の確認ではない**。iPhone（Safari）・Android の実機での確認は `docs/gates/GATE_0_DEVICE_CHECK.md` の手順で人間が行う
- PR・報告では「エミュレーションで確認」と書き、「実機で確認」と書かない

## 必要なもの

- Playwright（Chromium）。リポジトリの `@playwright/test`（E2E。Issue #16）か、環境に入っている `playwright` を使う。新しい依存は追加していない
- 日本語フォント IPA ゴシック、`git`、`npm`
- CI では実行しない（ビルドを 2 回行い時間がかかるため）。差分計算と撮影条件の単体テスト（`tests/unit/art-shots.test.mjs`）は CI で実行される

## 確認済みの動作（2026-11-19）

- `--base claude/issue-12-lp`（LP の PR #22）と作業ツリー（スクリプトの追加のみ）を比べ、18 区間すべてで変化 0・撮影上の問題なし・終了コード 0
- ペットの体の色を一時的に変えて比べ、ファーストビュー（全画面幅で 17,089 画素）と製品紹介（1,987 画素）だけが変化として検出され、`--fail-on-diff` で終了コード 1。確認後に変更は元に戻した
