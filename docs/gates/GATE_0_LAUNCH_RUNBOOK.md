## 3. 公開後の確認（手順 5）

公開した直後に、所有者が自分のメールアドレスで次を確かめる。テストとして集計から外すため、URL に `?ohuro_test=1` を付け、メールアドレスに `+ohuro-test` を付ける（EXPERIMENT_PLAN.md 4.4）。

1. `https://<公開URL>/?ohuro_test=1` を開き、`自分+ohuro-test@…` で登録する
2. 確認メールが届く（迷惑メールフォルダも確認）。送信者名・問い合わせ先・配信停止リンクが表示されている
3. メールのリンク → 確認ページ → 確認ボタンで登録完了になる
4. 任意アンケートに答えられる
5. 配信停止のリンクで「配信停止」と「データ削除」ができる
6. Gmail などの「配信停止」ボタン（ワンクリック配信停止）が表示される場合は、それでも停止できる
7. Supabase の SQL エディターで、テスト登録が `is_test = true` になっていること（読むだけ）
8. Vercel のログに、メールアドレス・トークン・API キーが出ていないこと
9. スマートフォンで横スクロールが出ないこと

問題があれば、配信を始めずに Issue を作る。

## 8. 保存期間を過ぎたデータの削除（公開後の運用）

期間は付録 A（D-013）。削除の処理は `scripts/waitlist/purge-expired.mjs`。**本番データの削除なので、実行は所有者が行う。**

1. 本番データベースの接続文字列を `PURGE_DATABASE_URL` として手元の環境に設定する（コマンド履歴やチャットに残さない）
2. 確認モードで件数を見る（何も変更しない）: `npm run waitlist:purge`
   - Gate 0 の判断から 1 年たった後は、計測イベントも対象にする: `npm run waitlist:purge -- --gate0-decided-at YYYY-MM-DD`
3. 件数が想定どおりなら削除する: `npm run waitlist:purge -- --execute`（必要なら `--gate0-decided-at` も付ける）
4. 実行した日と件数を記録する（メールアドレスは記録しない。出力にも含まれない）

- 頻度は所有者が決める（案: 週に 1 回。確認されなかった登録は 30 日を過ぎてから次の実行までの間、残る）
- 定期的に自動で実行する仕組み（スケジュール実行）は未設定。入れる場合は、本番の接続文字列を扱うため別途承認を得る
- 「公開のお知らせを送った後 6 か月」は、お知らせの送信日を記録する仕組みがないため未実装。お知らせを送る機能を作るときに追加する

## 付録 A. 登録データの保存期間（2026-11-21 決定。D-013）

「保存期間」は、**データの種類ごと**に「いつまで持ち、いつ消すか」を決めるもの。個人情報保護法では、利用する必要がなくなった個人データは遅滞なく消去するよう努めることとされている（条文は所有者・専門家が原文で確認する）。以下は選択肢の例で、**AI は期間の妥当性を保証しない**。

| データ | 何のために持つか | 選択肢の例 | 決定 | 現在の実装 |
|---|---|---|---|---|
| ① 確認済みの登録（メールアドレス・同意の記録・UTM） | 公開時のお知らせを送るため | (a) 公開のお知らせを送った後 ◯か月で削除 (b) 登録から最長 ◯年（公開が遅れても消す） (c) (a) と (b) の早い方 | お知らせ送信後 6 か月、または登録から 2 年の早い方 | 本人の削除依頼で即時削除。期限切れは「登録から 2 年」だけ `waitlist:purge` で削除（「送信後 6 か月」は未実装） |
| ② 確認されなかった登録（メールのリンクを押していない） | 確認を待つため（24 時間で確認リンクは無効） | 登録から ◯日（例: 7〜30 日）で削除 | 登録から 30 日 | `waitlist:purge` で削除 |
| ③ 配信停止した人の記録 | 再送しないため・同意の記録として | (a) すぐ削除 (b) 一定期間残す（同意と停止の記録を残す必要があるかは法務の確認事項） | 停止から 1 年（法務の確認事項） | 停止の日時を残す（「削除」を選んだ場合は消える） |
| ④ 任意アンケートの回答 | Gate 0 の判断材料 | (a) ① と同時に削除 (b) Gate 0 の判断後に個人と切り離して（メールアドレスを消して）残す | ① と同時 | 登録データと一緒に保存・削除 |
| ⑤ 計測イベント（個人を特定する情報なし） | 広告別の数字の集計 | Gate 0 の判断後 ◯年、または判断の記録を残した後に削除 | Gate 0 の判断から 1 年 | `waitlist:purge -- --gate0-decided-at <判断日>` で削除 |
| ⑥ レート制限用の値 | 連続送信の防止 | 現行のまま（1 日以内に削除） | 現行のまま | 実装済み |

③ の配信停止した登録と ④ のアンケートも `waitlist:purge` の対象（④ は登録と一緒に消える）。手順は 8 章。
